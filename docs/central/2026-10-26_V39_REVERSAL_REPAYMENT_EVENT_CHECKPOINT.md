# Local reversal and repayment event checkpoint — 2026-10-26

New full-sale reversals and customer debt repayments append a v38 `centralOperationalEvents` row in the same Dexie transaction as their immutable financial journal row. An event-write failure aborts the reversal or repayment. Retrying a successful submission key returns the saved record without another event. The schema remains v38; no historical transaction or migration is rewritten.

`sale.reversal_recorded` carries the exact saved reversal, original-sale shop if present, and `accounting_reversal_only` evidence. It does not assert that cash was paid out. `customer.repayment_recorded` carries the exact saved repayment with `local_record_only` settlement evidence. Its shop is null because one repayment can cover several sales or shops. Both preserve saved staff and shift IDs when present and leave device identity null. Delivery remains local only. Neither event is signed, server trusted, synchronized, or an independent payment confirmation.

Portable backup validation now dispatches by event kind, verifies the event against its matching journal row, and for reversals checks original-sale financial totals and scope. Unknown kinds fail closed. Existing cash partial refund events remain supported. A backup with no v38 operational events still represents its historical records honestly; no event is inferred or backfilled.

Focused credit, reversal and backup tests cover event contents, Dexie rollback on event failure, tamper rejection, and backup restore. The final full client run passed **1013/1013** across 125 files. Native QA passed **434/434** with localhost permission. TypeScript and the production Vite/PWA/Node build passed. The first full client attempt was interrupted without a result; a bail rerun identified two obsolete return-policy backup fixtures. Those fixtures were updated to preserve the separate policy-audit checks, and the final full run passed. See the `evidence/v39-*` logs and `evidence/v39-verification-2026-10-26.md`. This is an incremental source checkpoint, not a production acceptance decision.
