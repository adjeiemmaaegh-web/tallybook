## P0 — Must fix before any live commercial release (implementation and integration)
1. **Canonical inventory and cost ledger (Stages 2/3/12).** Define/store immutable receipts, returns, adjustments, units, batches, quantities and historical cost layers; create migrations/fixtures; reconcile imported/legacy records. Present FIFO `asOf` is a read-only preview; today's remaining stock cannot reconstruct historic balances. Verify historical sale cutoff, unit conversions, batch allocation, reversals, refunds, cost corrections, oversell, duplicate checkouts, partial orders and concurrency.
2. **Transactional checkout cost allocation and accounting (Stages 2/3/12).** Atomic stock decrement plus sale-line FIFO/lot cost allocation plus auditable COGS entry in one transaction; rollback if cost/stock insufficient or any write fails. Balance sale/payments/tax/discounts/loyalty/wallet/credit/reversals/repayments/refunds/expenses. Independently reconcile reporting against source ledgers, including failures and idempotent replay. No estimated/unsupported gross profit.
3. **Authorization and attribution (Stages 6/12).** Enumerate *all* write-service entry points (company/profile, staff, stock, purchases, checkout, returns, wallet, loyalty, credit, expenses, transfers, orders, backups/restore, automation). Validate active company, staff role, shift, permission, approvals, session, current device and actor at service boundary, not only UI. Preserve attributed audit records. Verify privilege escalation, cross-company access, direct IndexedDB tampering risks, unsafe restores. WebAuthn on supported secure-context hardware + PIN fallback and credential revocation must be verified or acceptance scope formally amended.
4. **Cloud identity, replication and recovery (Stage 8).** Make persistent authoritative organization/member/device identities, enrollment/revocation, hardened login/rate limits, TLS deployment with explicit proxy trust, expiring capabilities, durable multi-instance storage, idempotent outbox/inbox, server receipts, retry/replay semantics, conflict resolution, recovery checkpointing, cryptographic backup handling/key management and multi-device tests. Do not treat local optimistic acknowledgements as remote confirmation.
5. **Authoritative multi-store and attendants (Stage 9).** Per-store stock/cost balances, audited physical adjustments and actual transfers, store-attributed sales, owner consolidation based on source transactions. Mobile attendants must have scoped identity, revocation, offline queue, unique operation keys, durable sync, oversell prevention, deterministic conflict handling and end-to-end concurrent checkout testing. Current store counts are observations; transfer requests do not move stock.
6. **Public commerce and payments (Stage 10).** Public publishing/privacy/merchant consent, server-trusted prices, signed/authenticated customer orders, provider sandbox for intended MoMo/card rails, webhook signature and idempotency, server-side capture/refund/settlement reconciliation, stock reservations with expiry and atomic fulfillment, delivery tracking and dispute/refund handling. Public/live payments and inventory commitment must remain OFF until these pass. Local drafts are not paid orders.
7. **Data durability/recovery/migrations.** Run real IndexedDB migration paths from each supported old schema to 25, including 14–25; upgrade/downgrade safety, corrupt/truncated backups, large stores, company isolation, optional data, commerce drafts, staff/WebAuthn, batches, recovery verification, AES-GCM/passphrase integrity and rollback. No destructive migration without verified restore.
8. **Full production QA gate.** Clean reproducible dependency installation, all Vitest client tests, all Node tests, semantic TypeScript, Vite/esbuild production build, browser E2E/mobile/offline/PWA/device/hardware, security/authorization tests, load/performance, logging, accessibility, release smoke. Any failure is a blocker. Evidence must include exact commands, versions, logs, failures fixed, CI setup and release candidate hash.

## P1 — Stage scope still incomplete or needs qualification
9. **Stage 2 advanced inventory.** Confirm all catalogue variants/SKU/barcodes, multi-unit wholesale conversion, service/nonstock, product attachments, secure CSV import/export, persisted count sessions, batch/expiry/receiving and allocations, backup/migration, real scanner behavior; reconcile parallel Stage 2/Stage 3 source archives by behavior/diffs rather than wholesale replacing later code.
10. **Stage 3 full financial intelligence.** Accurate cash movement, receivables and ageing prerequisites, reconciliation on tax/discount/refund/repayment/loyalty/wallet; cost/profit/cashflow correctness and exports.
11. **Stage 5 assistant.** Complete quotation preparation transfer into actual quotation workflow, multi-turn customer tasks and record-grounded responses; no write action absent existing permissioned service. Add malicious-input and company-scope tests.
12. **Stage 7 offline suite.** Verify customer display isolation/nonmutation, phones/tablets responsive checkout, receipt printing/recovery and supported printers (ESC/POS adapter explicitly absent if required), notification consent/denial/browser differences, encrypted backup restore, PWA offline/reload, barcode/camera, keyboard/screen reader/accessibility, performance and error recovery.
13. **Stage 11 analytics.** Historical product/unit demand and defensible reorder quantities grounded in stock/cost/return history, live batch-expiry IndexedDB pipeline, receivable due dates and allocations for truthful debt ageing, persisted permissioned automation rules/approval flow/notifications; prevent unauthorized autonomous financial writes. Current suggestions are advisory only.
14. **Operational/security readiness.** Threat model, CSP/CORS/CSRF/cookie/session config, secret management, encryption-at-rest boundaries, logging redaction, dependency audit/SBOM, data deletion/privacy/consent, backup retention, audit exports, production monitoring and incident/recovery drills. These are acceptance categories to verify; not a claim each has a confirmed defect.

## Release-gate policy
No COMPLETE / production-ready claim until every in-scope P0/P1 requirement is implemented and independently tested, all tests/types/build and migrations pass, real device/provider gates pass, and a signed-off scope + evidence manifest is delivered. If external credentials/hardware are missing, record exact blocker and provide sandbox/test harness instructions. Don't fabricate runs or waive risk silently.
